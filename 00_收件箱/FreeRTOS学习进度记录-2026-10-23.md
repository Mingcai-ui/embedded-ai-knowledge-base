# FreeRTOS 学习进度记录（2026-10-23）

> **阶段**：任务A（任务挂起/恢复）＋ 任务B（消息队列）
> **平台**：STM32F103C8T6 / HAL / FreeRTOS 10.3.1（CMSIS-OS2）/ VS Code + EIDE
> **配套**：[[CMSIS-RTOS2函数速查表-STM32CubeMX版]]

## 一、本阶段做了什么

- 任务A：Key1 边沿触发，挂起/恢复 defaultTask（PA6）；LEDTask（PA7）全程不受影响。
- 任务B：Key2 通过 LEDQueue 发模式号，LEDTask 按 0/1/2 切换 1000ms / 500ms / 200ms 翻转。
- 环境整理：堆 3072 → 10240；核对 CubeMX 参数、`.ioc` 与生成代码三者一致性。

## 二、能力判定

判定标准：能自己定位到具体行、说清机理、给出验证手段、修完能复现验证 —— 四条全中才算掌握。

### 已掌握（能独立定位并解释）

1. **阻塞点纪律**：任何任务循环必须有 `osDelay` 或阻塞调用，否则高优先级任务空转会把其他任务饿死。
2. **按键边沿触发**：二次确认 + 等待松手，防止按住连发；每条分支都要有阻塞。
3. **意图变量优于状态查询**：`osThreadGetState` 把 `eBlocked` 与 `eSuspended` 合并成 `osThreadBlocked`，不能用来判断"是否被挂起"，必须自己维护 `paused` 标志。
4. **队列的本质**：按字节 `memcpy`，`uxItemSize` 是唯一真相，传什么类型的指针它都不检查。
5. **阻塞语义不对称**：`Put` 的 timeout 只在队列满时生效；`Get` 的 timeout 是"等多久没消息就放弃"。
6. **三个真相源**：`.ioc`（源头）、生成代码（编译值）、`elf`（实际运行）必须一致；不一致时先看时间戳。
7. **任务函数不能 return**：返回会进 `prvTaskExitError` / 断言，任务永久消失。

### 半懂（踩过坑，需要能完整复述机理才算过）

1. `Put` 的 `osWaitForever` —— 曾判断为"osWaitForever 有 bug，改成 0 就好"，实际它只在队列满时才阻塞。
2. 队列字节数一致性 —— 1 字节的队列装 4 字节数据，静默截断，表现为闪烁频率不变。
3. 堆预算 —— `FootprintOK=false` 的来源，任务栈 + 队列 + 定时器 + TCB 的估算方法。

### 未验证（本阶段最大缺口）

1. 编译 → 烧录 → 观察的闭环：出现过源码 13:24、elf 却是前一天 20:47 的情况。
2. 调试器取证：`uxItemSize` / `uxLength` / `pxCurrentTCB` / `xPortGetFreeHeapSize` 还没在实际排错中用过。
3. 队列改成 16 × `uint32_t` 之后的实测结果尚未回报。

## 三、六个真实故障档案

1. **高优先级任务无阻塞** —— 全系统饿死，表现是"所有灯突然定格"，不是死机。
2. **按住时重复 vTaskDelete**（句柄未置空）—— 操作已释放的 TCB，进断言死循环或 HardFault。
3. **用 osThreadGetState 决定挂起还是恢复** —— 永远走 Resume 分支，表现为"按键没反应"。
4. **队列 Item Size = uint8_t，代码却按 uint32_t 收发** —— switch 永不命中，表现为"频率不变"。
5. **改完没编译** —— 测的是旧固件，所有现象都是昨天的。
6. **FootprintOK = false** —— 每次生成都报 `[FREERTOS]` 警告，但界面上没有任何红叉。

## 四、评估结论

- **结论：会用，尚未到掌握。**
- **支撑**：能读懂机理并自己写出结构正确的代码（任务A 的挂起逻辑、Key1/Key2 的分支结构都是自己搭的）；但本阶段 4 个真实故障里，有 3 个是在被指出后才修正的。
- **主要短板**：缺"主动取证"的习惯 —— 现象出现时先改代码试，而不是先用时间戳、Watch、断点确认。
- **位置判断**：已经过了"能写能跑"这一档；距离"能定位、能解释、举一反三"还差一个调试器取证的习惯。

## 五、下一步（按优先级）

1. **建立闭环习惯**：每次改动先确认 `build/Debug/*.elf` 时间戳变了，再讨论现象。
2. **把四个 Watch 用熟**：
   - `((Queue_t*)LEDQueueHandle)->uxItemSize`
   - `((Queue_t*)LEDQueueHandle)->uxLength`
   - `pxCurrentTCB->pcTaskName`
   - `xPortGetFreeHeapSize()`
3. **队列类型单一真源**：`typedef` 一个 `LEDMsg_t`，CubeMX 的 Item Size 直接填这个类型名；加 `_Static_assert` 做编译期校验。
4. **LEDTask 用 Get 的超时当节拍**：`Get(..., Time_Delay)`，超时即翻转，变速延迟压到一个周期内，也不会积压。
5. **下一阶段**：任务通知 / 软件定时器（任务C），对比三种机制；之后再上互斥量与优先级反转。

## 六、一句话总结

这一阶段真正学到的不是 API，而是两件事：**任务必须阻塞，数据必须对齐字节。**
