# P0 学习内容与视频取舍

> 项目：[[Modbus边缘采集网关-主档卡]]｜前置：[[清单_2026-10-30_网关底层四项]]
> 本文回答三件事：P0 要学什么、每项学到什么程度、哪些视频该跳。

## 先给结论

**P0 几乎不需要视频。** 五个板块里四个你已经具备（HAL 外设、DMA+IDLE、定时器、CRC 正在学），剩下两个（RS485 硬件、Modbus 帧格式）都该看**文档和规范**，不是看视频。

视频教程讲 Modbus 的通病：从 485 电平标准讲到 PLC 组态、从站编程，两三小时里真正能用在 C8T6 上的不到 20 分钟。P0 需要的 Modbus 知识，一页帧格式表加手算三帧就够。

---

## 一、P0 的能力终点

**一句话**：PC 上的 Modbus Poll 发一帧 `01 03 00 00 00 0A`，你的板子回出正确应答，且 CRC 一个字节不差。

**验收物**（三样，缺一不算过）：

1. 串口助手能看到自己发出的请求帧和收到的应答帧，字节级对照
2. CRC16 三组向量全对 + 反向校验归零
3. 状态机能白板画出，每个跳转条件说得清

---

## 二、五个板块 · 学到什么程度

深度三档：**会写**（能独立实现并讲原理）／**会用**（能改能调）／**知道**（查得到就行）

### 板块 1 · RS485 物理层与 MAX485

| 项 | 内容 |
|---|---|
| 要学什么 | 差分 A/B 极性、终端电阻 120Ω 位置、DE/RE 方向控制时序、共地问题 |
| 深度 | **会用**（不要求会设计收发电路） |
| 关键坑 | 发送完成中断之后才能切方向位，早一个 bit 就截断末字节；DE 上电必须是低电平（否则开机抢总线） |
| 靠什么学 | MAX485 数据手册前 3 页 + 实测。**不需要视频** |
| 判断标准 | 能说出：为什么切早了会丢最后一个字节、为什么 120Ω 只接总线两端 |

> 这是 P0 里唯一有"物理不确定性"的部分，也是唯一必须上板实测的部分。

### 板块 2 · STM32 外设配置

| 项     | 内容                                                         |
| ----- | ---------------------------------------------------------- |
| 要学什么  | USART2 + DMA Circular + IDLE 中断；TIM2 分频到 1µs；RS485_DE GPIO |
| 深度    | **会写**                                                     |
| 现状    | 已具备（[[UART空闲中断接收不定长数据_IT与DMA双方案]]、[[环形缓冲区]] 已验证）           |
| 靠什么学  | 不用学，按 [[清单_2026-10-30_网关底层四项]] ① 的 CubeMX 表直接配             |
| 判断标准  | 上电打印 `boot ok, clk=72MHz, tim2=1us`                        |
| 唯一新增点 | TIM4 是 HAL 时基，**不能拿来当 3.5T 计时**，必须用 TIM2                   |

### 板块 3 · Modbus RTU 协议

| 项    | 内容                                                 |
| ---- | -------------------------------------------------- |
| 要学什么 | 帧格式、地址域、功能码 03、异常码、字节序、3.5T                        |
| 深度   | 03 功能码 **会写**；06/16 **知道**（P3 再细）；异常码 01–04 **知道** |
| 靠什么学 | Modbus 应用协议规范（中文译本）+ 手算帧。**看视频性价比极低**              |
| 判断标准 | 见下方"三帧手算"，全对才算过                                    |
|      |                                                    |

**帧格式（RTU）**：

```
[从机地址 1B] [功能码 1B] [数据 nB] [CRC 低字节 1B] [CRC 高字节 1B]
```

**请求 03（读保持寄存器）**：

```
01 03 00 00 00 0A C5 CD
│  │  │     │     └─ CRC = 0xCDC5，低字节先发
│  │  │     └─ 寄存器数量 10
│  │  └─ 起始地址 0x0000
│  └─ 功能码 03
└─ 从机地址 01
```

**应答 03**：

```
01 03 14 <20 字节数据> CRC
      └─ 字节数 = 寄存器数 × 2
```

**异常应答**：功能码最高位置 1

```
01 83 02 41 12     ← 83 = 03|0x80；02 = 非法数据地址
```

**异常码**：

| 码 | 含义 | P0 会遇到的场景 |
|---|---|---|
| 01 | 非法功能 | 从机不支持该功能码 |
| 02 | 非法数据地址 | 读超出寄存器范围 |
| 03 | 非法数据值 | 数量超限（>125） |
| 04 | 从机设备故障 | 从机内部错误 |

### 板块 4 · CRC16

| 项 | 内容 |
|---|---|
| 深度 | **会写**，且必须手写不用查表数组 |
| 现状 | 2026-10-30 已学原理与实现，未上机验证 |
| 判断标准 | 三组向量 + 反向归零（详见 [[清单_2026-10-30_网关底层四项]] ②） |

关键点复述（防忘）：

- 多项式 `0x8005` 逐位反转 = `0xA001`，右移算法必须用 `0xA001`
- 初值 `0xFFFF`，输出不取反
- 发送时**低字节在前**
- 反向校验必须**按发送顺序**追加才归零；按高字节先追加得 `0x0606`，别以为代码错了

### 板块 5 · 状态机编程

| 项 | 内容 |
|---|---|
| 深度 | **会写 + 会画**。这是你的短板，P0 最重要的产出其实是这个 |
| 靠什么学 | 没有好视频，靠画和写。**不许让 AI 先写** |
| 判断标准 | 白板 5 分钟画出接收状态机，每个跳转条件口述清楚 |

**P0 接收状态机目标形态**（先自己画，画完再对照）：

| 状态 | 进入条件 | 动作 | 跳转 |
|---|---|---|---|
| IDLE | 上电 / 帧处理完 | 等首字节 | 收到字节 → RX |
| RX | 首字节到达 | 入环形缓冲、重置 3.5T 计时 | 3.5T 超时 → FRAME_END |
| FRAME_END | 3.5T 到期 | 锁定帧长 | → VERIFY |
| VERIFY | 帧长已定 | CRC 校验 | 过 → DISPATCH；不过 → 丢帧计数 → IDLE |
| DISPATCH | CRC 通过 | 比对地址与功能码 | 匹配 → 处理→应答；不匹配 → IDLE |

三个必须能答的问题：

1. 帧内字节到达间隔小于 3.5T 时，计时器要怎么重置？重置错了会怎样？
2. CRC 失败要不要回异常帧？（不能——CRC 错的帧连地址都不可信）
3. 帧长上限怎么定？溢出保护做在哪一层？

## 四、深度速查

| 技能 | 必须能 | 允许查手册 |
|---|---|---|
| CRC16 | 默写 8 行位运算实现 | 向量值 |
| 03 帧组帧/解析 | 手写，含字节序处理 | 异常码表 |
| 3.5T 判定 | 讲清 9600 / 115200 下各是多少 µs | 精确协议阈值 |
| 状态机 | 白板画 + 口述跳转 | — |
| MAX485 时序 | 讲清为何必须等发完再切 | 引脚定义 |
| RTOS API | 知道该用哪个 | 函数签名与参数 |

**3.5T 数值（自己验算一遍再记）**：

| 波特率 | 1 字符（11 bit） | 3.5 字符 |
|---|---|---|
| 9600 | 1.146 ms | 4.01 ms |
| 19200 | 0.573 ms | 2.01 ms |
| 115200 | 95.5 µs | 规范固定用 **1750 µs** |

> 规范规定 >19200 bps 时 t3.5 固定取 1.75 ms、t1.5 取 750 µs，不按字符时间算。这条是硬性规定，答不出来会被追问。

## 六、不许进 P1 的红线

任一条不满足就停在 P0：

- [ ] CRC 三组向量全对，且改任一字节 CRC 必变
- [ ] 反向校验按发送顺序追加得到 0x0000
- [ ] 状态机能白板画出，5 个跳转条件全部讲清
- [ ] Modbus Poll 能读到真实传感器数据，应答 CRC 校验通过
- [ ] 故意发一个 CRC 错帧，板子丢弃且不回应答
- [ ] 能讲清"为什么 CRC 错帧不回异常码"
