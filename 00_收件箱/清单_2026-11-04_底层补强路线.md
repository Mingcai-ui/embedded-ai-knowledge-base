# 底层补强路线（看手册 vs 看视频 + 重点清单）

> 定位：排查方法论（软件篇/物理篇）背后缺的"为什么"。排查卡壳，多半不是不会操作，而是**不懂底层**。
> 我的短板排序（[[个人画像]] 第 9 节）：英语 > 理论八股错位 > C 深水区 > Git。本篇按"排查最需要"重排，不是按画像排序。

---

## 0. 先回答：看手册还是看视频？

**结论：视频入门，手册深入，两者分工，别二选一。**

| 维度 | 视频（B 站/教程） | 官方手册（RM/DS/PM） |
|---|---|---|
| 干什么用 | 建立**画面感**、知道"有这么个东西、长这样、大概怎么用" | 建立**精确事实**、查"这个寄存器第几位是啥" |
| 优点 | 快、有演示、跟得上 | 权威、无二手错、可查、可引 |
| 缺点 | 讲者可能错、讲不透原理、看完记不住细节 | 全英文、信息密度大、枯燥 |
| 什么时候看 | **入门一个新外设/概念时**（先看视频懂个大概） | **要落地/要排查时**（写代码和排 bug 时查手册） |

### 我该用的组合拳

1. **新外设**：先 30 分钟视频建立画面 → 打开 CubeMX 配一遍看生成代码 → 查手册对应寄存器章节。
2. **写代码时**：CubeMX + HAL 库函数注释（`HAL_xxx` 头部有说明）为主，手册寄存器章节为辅。
3. **排 bug 时**：**手册优先**。视频救不了"为什么中断不触发"，手册寄存器描述能。

> 关键提醒：**视频是别人嚼过的，手册才是原汤**。排查必须回到手册，因为视频不会讲你的具体 bug。

## 1. 手册体系（先搞清"看哪本"）

STM32 有三类官方文档，各司其职：

| 缩写 | 全称 | 讲什么 | 什么时候看 |
|---|---|---|---|
| **RM** | Reference Manual（参考手册） | 外设寄存器每一位的含义、功能框图 | **排 bug 主战场** |
| **DS** | Datasheet（数据手册） | 电气参数、引脚定义、封装、极限值 | 查引脚、查电压/电流/时序极限 |
| **PM** | Programming Manual（编程手册） | Cortex-M 内核、指令集、NVIC、SysTick | 查内核级（中断、异常、寄存器 SCB） |

**排 bug 优先级**：RM > DS > PM。
- "中断不触发" → RM 的 EXTI/NVIC 章 + PM 的 NVIC 章。
- "引脚不对" → DS 的 pinout 表。
- "HardFault" → PM 的 Fault 章节（CFSR/BFAR 那套，见软件排查篇 §5）。

> 中文版：正点原子/野火的手册是 RM 的**中文注解版**，可当 RM 的"导读"，但**最终结论仍以英文原版为准**（这也是画像短板 #1 英语要攻的地方，读文档靠中文是硬伤）。

## 2. 手册必读章节清单（按排查频率排序）

### 2.1 时钟树（RCC）—— 最高频的"隐性 bug 源"

- **看哪**：RM 的 Reset and clock control（RCC）章，重点是**时钟树图**。
- **为什么**：波特率错、定时器周期不对、外设不工作，根源常是时钟配错（见 [[FreeRTOS_阶段一故障合集]] 坑8）。
- **必掌握**：HSI/HSE/PLL 关系、APB1/APB2 分频、各外设挂哪条总线、`SystemCoreClock` 怎么算。

### 2.2 中断与 NVIC（EXTI / 内核中断）

- **看哪**：RM 的 EXTI 章 + PM 的 NVIC 章。
- **必掌握**：优先级分组、抢占/子优先级、`ISER`/`IPR`、BASEPRI（关中断的真实语义，见 [[FreeRTOS_中断管理与临界区]]）。

### 2.3 GPIO / 复用（AFIO）

- **必掌握**：输入上拉/下拉、推挽/开漏、复用功能、`IDR`/`ODR` 只读只写。
- **排查点**：引脚复用了但没开 AFIO 时钟、开漏没上拉、方向配错。

### 2.4 定时器（TIM）

- **必掌握**：`PSC`/`ARR` 算周期（`T=(PSC+1)(ARR+1)/f`）、`CR1.CEN`、`DIER.UIE`、`SR.UIF`。
- **排查点**：只 `Init` 不 `Start_IT`（坑7）、ARR 默认 65535（坑8）。

### 2.5 DMA

- **必掌握**：通道映射、传输方向、半传输/传输完成中断、双缓冲。
- **排查点**：DMA 配了但对应外设的 DMA 使能没开、缓冲区没对齐。

### 2.6 UART / I2C / SPI（通信外设）

- 每个外设查：帧格式（数据位/停止位/校验）、波特率来源、状态寄存器错误标志（ORE/FE/NE）、中断使能。

## 3. C 语言深水区补强（画像短板，也是 M1 模式的根）

> 错误总表里 M1「用类型/地址推断数据」占了 5 条，全部指向 C 语言不扎实。这是**排查能力的地基**，必须补。

### 3.1 必补清单（按对排查的影响排序）

| 主题 | 为什么关键 | 对应我犯的错 |
|---|---|---|
| **数组名 vs 指针** | `sizeof` 对数组和对指针结果不同 | E01（把指针当数组 sizeof） |
| **指针与地址运算** | 越界、野指针、解引用 | HardFault 主因 |
| **类型宽度与隐式转换** | `uint8`/`uint32` 混用、符号回绕 | E02、E03 |
| **字节序（大小端）** | 协议字节顺序、结构体序列化 | E13（CRC 低字节先） |
| **`volatile` / `const` / `static`** | 中断共享变量、只读、作用域 | 竞态 bug |
| **结构体 / 联合体 / 对齐 / `packed`** | 内存布局、寄存器映射、`sizeof(结构体)` | UNALIGNED fault |
| **位操作（移位/掩码/或与）** | 寄存器读写基本功 | 所有外设 |
| **栈 vs 堆 / 内存布局** | 栈溢出、`malloc` 泄漏、段分布 | FreeRTOS 栈溢出 |

### 3.2 怎么补（可执行）

1. **《C 和指针》+ 手写题**：画像里"链表题无印象""数据结构 68 分"，说明**指针/内存这块要动手写**，光看不行。
2. **每个坑配一段最小代码**：`sizeof(数组)` vs `sizeof(指针)` 各写一遍，`volatile` 用中断改变量验证一遍。
3. **用 `_Static_assert` 验证类型假设**：把"我以为 Item Size 是 4"变成编译期断言（[[FreeRTOS_阶段一故障合集]] 坑4 的解法）。

## 4. 编译与链接基础（排查"诡异现象"的底层）

> 很多"改了没生效""变量值莫名变"，根因在编译/链接层，不在源码。

### 4.1 必懂概念

| 概念 | 为什么排查需要 |
|---|---|
| **编译三阶段**：预处理 → 编译 → 链接 | 定位"宏没生效/符号找不到" |
| **优化等级**（-O0/-Og/-O2） | `<optimized out>`、变量被优化掉、时序被重排 |
| **段（section）**：`.text`/`.data`/`.bss`/`.stack` | 看 map 文件、查内存溢出 |
| **map 文件** | 看函数/变量放哪、内存分布、栈/堆大小 |
| **栈 vs 堆大小配置** | 栈溢出、`malloc` 失败 |

### 4.2 排查动作

- 现象"改了没生效" → 先查是不是没重新编译（坑5），再查优化等级。
- 变量莫名被改 → 查 `volatile`、查是否数组越界覆盖相邻变量（看 map 文件内存布局）。
- `undefined reference` → 链接问题，查是否漏了 `.c` 文件或库。

## 5. 寄存器思维（从 HAL 抽象往下钻）

HAL 库屏蔽了寄存器，但排查必须能往下钻一层：

- **会读**：`__HAL_TIM_GET_FLAG(&htim, TIM_FLAG_UPDATE)` 背后是读 `SR.UIF`。
- **会看**：调试器 Peripherals 面板直接看寄存器（软件排查篇 §4.2）。
- **会查**：手册找到寄存器位定义。
- **目标**：不是背寄存器，而是"知道每个 HAL 函数动了哪些寄存器、哪几位"，排查时能对应到手册。

## 7. 三个"最容易被忽略但我一定会遇到"的底层坑

1. **`volatile` 不写，中断改的变量主循环读不到**：编译器把变量缓存到寄存器，主循环永远读旧值。凡是"中断里改、主循环读"的变量，必须 `volatile`。
2. **数组越界不报错，悄悄覆盖隔壁变量**：C 不做边界检查，越界写会覆盖栈上相邻变量，现象是"某个无关变量莫名变了"。查法是看 map 文件内存布局 + 用内存视图。
3. **隐式类型转换的符号扩展**：`uint8_t` 参与运算前会被提升成 `int`，有符号数右移/比较常出错。写位操作和协议解析时，显式 `uint32_t` 再移位。
