# 进度 · 调度器挂起与恢复（源码精读）

> 入口：从 `vTaskDelay` 底层跳入 `vTaskSuspendAll` / `xTaskResumeAll`。属任务A 之后的源码层精读，不是 API 用法复习。
> 关联：[[FreeRTOS_索引]]、[[FreeRTOS_学习进度_2026-10-24]]

## 一、学了什么

对象：`vTaskSuspendAll` / `xTaskResumeAll`，以及它们和 `xTaskResume` / `xTaskResumeFromISR` 的交叉点。

能独立复述的链路：

`vTaskDelay` → `vTaskSuspendAll`（`++uxSchedulerSuspended`）→ `prvAddCurrentTaskToDelayedList` → `xTaskResumeAll`（自减到 0 才真正恢复）→ 搬 pending → 重算 unblock time → 补节拍 → 按标记 yield。

正确的事实清单：

- 挂起用**计数**不用布尔，因此允许嵌套；`xTaskResumeAll` 开头有 `configASSERT(uxSchedulerSuspended)` 兜住不配对调用
- 非 0 期间 `taskYIELD` 宏内部判断后跳过 `portYIELD`，即挡住的是 PendSV，不是中断
- 挂起期间 `xTickCount` 停增，改 `++xPendedTicks`；恢复时用局部副本 `xPendedCounts` 做 do-while 补算，最后 `xPendedTicks = 0`
- 挂起调度器 ≠ 关中断：中断照常响应、ISR 照常 give，只是不切任务

## 二、能力判定

### 已掌握

- 主链路时序（挂起→入延时表→恢复→补节拍）能按顺序讲清
- `xPendingReadyList` 的定位：挂起期间被唤醒任务的寄存区，恢复时统一搬回就绪表
- 能识别 ISR 版本：`portSET_INTERRUPT_MASK_FROM_ISR()` 是 `xTaskResumeFromISR` 的标志，不属 `xTaskResumeAll` 内部
- "中断只能通知、不能切任务"这条边界（PendSV 语义）已通

### 半懂

| 题 | 判定依据 |
|---|---|
| 挂起期间被唤醒任务的**节点归属** | 会背恢复流程，但没答出「TCB 有两个链表项成员，分别服务不同链表」这个结构事实 |
| `xEventListItem` vs `xStateListItem` 的选择 | 动机对（唤醒时已摘空、可复用、省内存）；后果说错——不是"所有任务状态被覆盖清零、程序崩溃"，而是只破坏**当前任务**的链接，导致延时列表断裂、遍历取到非法 TCB |
| `xYieldPending` / `xAlreadyYielded` | 两个都定位错：前者不是"中断消费"，后者不是"给 CPU"，它是函数**返回值**，消费者是调用者 |
| 挂起期间能否阻塞 get | 结论对；判据说成"时长短"，实际判据是"会不会把自己挂进延时列表"。0 超时确实不阻塞、可行，但理由是"不阻塞"而非"不耗时" |

### 未验证

| 题 | 判定依据 |
|---|---|
| 挂起期间延时到期是否进 pending list | **结论对、理由错**。答成循环论证（"只有就绪列表能用"）。真正原因：挂起时 `xTaskIncrementTick` 直接走 `++xPendedTicks` 分支，延时列表根本没被扫描——"到期"这件事在挂起期间**没有发生**，它发生在恢复补算时，那时调度器已恢复，直接进就绪列表 |
| 搬任务时为什么要二次 `uxListRemove` | **答错**。把 `xStateListItem` 当成了"记录运行到哪"（运行上下文在 TCB 的 port 层 / `pxTopOfStack`，不在链表项里）。它记录的是"任务当前挂在哪个链表"；挂起分支**故意没摘**它，恢复时必须补摘，否则任务同时存在延时表与就绪表，双挂 |

## 三、本轮被纠正的三处（错误锚点）

| 我原来的理解 | 实际 | 后果 |
|---|---|---|
| `xStateListItem` 记录任务运行到哪 | 记录"任务挂在哪个链表"，是位置凭证 | 会推出"不摘也没事"的错误结论 |
| 挂起期间到期任务该进 pending list | 挂起期间 tick 不增，延时表不被扫描 | 把 `xPendedTicks` 机制的必要性理解成"可选优化" |
| `xYieldPending` 是中断消费、`xAlreadyYielded` 给 CPU | 前者是"欠一次调度"的全局标记，由 `vTaskSwitchContext` 在执行切换时消费与清零；后者是 `xTaskResumeAll` 返回值，指示"我已 yield 过，你别再 yield" | 两个变量的生产者/消费者关系不成立，读 `vTaskDelay` 收尾代码时会猜 |
