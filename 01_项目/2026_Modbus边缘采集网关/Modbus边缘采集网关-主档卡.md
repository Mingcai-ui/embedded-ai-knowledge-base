# Modbus 边缘采集网关 · 主档卡

> **定位**：毕业设计 + 秋招面试 + 12 月广西赛的**唯一主线项目**（一鱼三吃）。
> 核心一（Modbus 协议栈）与核心二（零丢帧流水线）不是两个项目，是同一台网关的协议层与数据层。

## 一句话目标

面向只有 RS485 接口、无 IP 能力的工业存量设备，做一台**协议可解析、故障可隔离、数据不丢失、断网可续传**的 Modbus RTU → MQTT 边缘采集网关。

## 为什么这是一个"完整项目"

数据链路一条线贯穿两个核心：

```
[从机1] 温湿度表 ─┐
[从机2] 电表 ─────┼─ RS485 总线 ─ MAX485 ─┐
[从机3] 传感器 ───┘                        │
                            ┌──────────────▼─────────────────┐
                            │ STM32F103 + FreeRTOS           │
                            │ ① 核心一：Modbus RTU 协议栈     │
                            │    3.5T 帧检测 / CRC16 / 轮询调度│
                            │ ② 核心二：零丢帧流水线          │
                            │    DMA+IDLE → 环形缓冲 → 队列   │
                            │ ③ 核心二：W25Q64 离线缓存       │
                            └──────────────┬─────────────────┘
                                           │ UART
                            ┌──────────────▼─────────────────┐
                            │ 上行模组（WiFi / 4G）           │
                            │ MQTT QoS1 + 断线重连 + 补传     │
                            └──────────────┬─────────────────┘
                                           ▼
                                [云平台 / 上位机可视化]
```

- 核心二是核心一的**物理底座**：Modbus 应答帧经 UART 进入，DMA+空闲中断+环形缓冲就是协议栈的接收通道。
- 单独看，每个核心是一个"技术攻坚点"；合起来是硬件→协议→可靠性→云端的完整闭环，工作量与论文篇幅达到毕设级。

## 阶段计划

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 单主单从链路打通：Modbus 03 读取 + 串口上 PC | 串口工具读出真实传感器数据 |
| P1 | 零丢帧流水线 + 3 从机轮询 + 超时预算 | 丢帧率测试；1 从机掉线不阻塞总线 |
| P2 | W25Q64 离线缓存 + 掉电恢复 + 看门狗 | 掉电数据可恢复；断网恢复后补传 |
| P3 | MQTT 上云 + 上位机可视化 + 远程写（06/16） | 云端实时曲线 + 下发控制生效 |
| P4（可选） | K230 视觉事件通道：识别结果按从机事件接入网关 | 视觉告警 → MQTT 事件上报 |

> P4 说明：K230 不作为核心，只是"挂在网关上的一个事件源"，复用校赛现成帧协议。答辩主线仍是网关本身。

## 可量化验收指标（论文测试章素材）

1. 轮询周期与时延上界（N 个从机下的实测值）
2. 丢帧率曲线：环形缓冲深度（1K/4K/8K）vs 丢帧率
3. 故障隔离：单从机掉线时其余从机数据新鲜度不受影响
4. 数据完整性：断网 1 小时后补传完整率 100%

## AI 不可代写边界（纪律）

- **必须手写并逐行吃透**：3.5T 帧检测状态机、CRC16、轮询调度器、环形缓冲判空/判满与 overrun 策略、W25Q64 分页写/擦除逻辑
- AI 只做加固：CubeMX 初始化、上位机界面、文档
- Git：本项目仓库**自己建、自己推**（补上零基础的短板）
