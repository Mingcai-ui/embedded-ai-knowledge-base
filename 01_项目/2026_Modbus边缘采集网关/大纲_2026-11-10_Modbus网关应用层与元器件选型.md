## 1. 应用层选型：数据为谁服务

### 1.1 只回答一个问题

> **中小机房 / 车间里"会转但没人看"的设备（风机、水泵、机柜内设备），如何用低成本改造，让它们的运行状态自己上报？**

项目交付的答案：贴在设备上的多传感器节点（0x02）→ 一条 RS485 总线 → 网关协议解析与故障隔离 → MQTT 上云 → 输出四种设备状态：**运行 / 停机 / 振动异常 / 被移动（倾角）**。

### 1.2 候选场景对比（为什么选 A）

| 场景                   | 传感器匹配       | 与网关叙事            | 可演示性         | 结论                                     |
| -------------------- | ----------- | ---------------- | ------------ | -------------------------------------- |
| **A 设备状态监测**（振动+温湿度） | MPU6050 正好用 | 与"存量设备改造"同构      | 电机开/停/敲击即可演示 | ✅ **选定**                               |
| B 冷链运输箱（温湿度+冲击）      | 部分匹配        | 需要移动供电/4G，偏离网关主线 | 要跑起来演        | ❌                                      |
| C 机柜防盗/防拆（倾角）        | MPU6050 复用  | 匹配               | 好演           | 🟡 **作为 A 的附属场景**（同一传感器，零新增硬件，答辩多一个故事） |
| D 农业大棚（温湿度）          | MPU6050 用不上 | 弱                | 一般           | ❌                                      |

选 A 的硬理由：
- MPU6050 的振动/倾角数据有明确去处，不再是"屏上刷原始码流"的 demo；
- 面试可深挖点多且自洽：阈值怎么定、误报怎么防、为什么不用 FFT（见 1.6）；
- 与 12 月竞赛任务书同构（感知 + 网络 + 云端）。

### 1.3 数据价值阶梯（三层，计算边界冻结）

| 层 | 内容 | 在哪算 | 边界 |
|---|---|---|---|
| L1 原始值 | 加速度/角速度/芯片温度/温湿度 → 寄存器地图 | 节点采样 | 100ms 节拍，只进寄存器 |
| L2 工程量 | 振动强度 RMS（1s 窗口）、倾角（加速度重力投影）、设备状态位 | **节点** | **只做时域统计**；禁止 FFT、禁止 DMP 姿态融合、禁止卡尔曼、禁止机器学习 |
| L3 事件 | 振动超限 / 停机 / 倾角异常 / 从机离线 | 网关判定并上行 | MQTT 事件帧，一行 JSON，不做复杂规则引擎 |

**为什么 L2 放节点不放网关**（面试必答）：① 省总线带宽——主站轮询状态位即可，不必每轮搬原始码流；② 职责分层——节点懂传感器，网关懂协议；③ 总线拥塞/轮询未到也能本地报警。

**阈值与误报策略（冻结版）**：
- 基线自学习：上电前 N 分钟（宏配置，默认 5min）采集 RMS，取均值 + k 倍偏差（默认 3）作阈值；支持寄存器写入手动阈值覆盖。
- 防误报：连续 3 次超限且持续 ≥2s 才置"异常"（复用校赛"连续帧确认"的同款思想，面试可主动串联）。
- 停机判定：RMS 低于停机阈值持续 ≥5s。

### 1.4 寄存器地图（冻结版，0x02 传感器节点）

与 [[进度_2026-11-10_Modbus传感器节点方向确认]] 的槽位规则一致：设备信息区 0x00–0x0F，每传感器固定 8 格，**加传感器不动已有地址**。

| 地址 | 内容 | 类型/缩放 |
|---|---|---|
| 0x00 | 设备型号码 | uint16 |
| 0x01 | 固件版本 | uint16（0x0100=v1.0） |
| 0x02 | 运行时长 | uint16，分钟，回绕不管 |
| 0x03 | 错误码（传感器初始化/采样故障） | uint16，0=正常 |
| 0x04 | 设备状态位（0 停机/1 运行/2 振动异常） | uint16 |
| 0x05 | 倾角 | int16，×10，单位 0.1° |
| 0x06 | 振动强度 RMS | uint16，×100 |
| 0x07 | 异常事件累计次数 | uint16 |
| 0x10–0x17 | **槽1 DHT11**：0x10 温度×10（int16），0x11 湿度×10，余预留 | — |
| 0x18–0x1F | **槽2 MPU6050**：0x18–1A 加速度 XYZ 原始码（int16），0x1B–1D 角速度 XYZ，0x1E 芯片温度×10，0x1F 预留 | — |
| 0x20–0x27 | **槽3 预留**（下一个传感器直接占这里） | — |

共 40 个寄存器 → 代码侧 `NUMBER_OF_REGISTER` 由 10 扩到 40。
只开放 0x03 读 + 0x06 写阈值（0x06 写是唯一定点写入口，其余写功能码回异常 0x01）。

### 1.5 演示脚本（竞赛/答辩通用，5 个场景）

1. **正常运行**：电机带动振动源，云端曲线周期性波动，状态位=1；
2. **停机**：关电机 → RMS 跌破停机阈值 → "停机"事件上报，状态位=0；
3. **振动异常**：敲击/松动振动源 → RMS 超限持续 2s → "异常"事件 + 节点本地蜂鸣/LED；
4. **被移动**：搬动节点 → 倾角突变 → "倾角异常"事件（附属场景 C）；
5. **断网补传**：拔上行链路 → 事件与数据入 W25Q64 → 恢复后补传完整。

### 1.6 面试包装

**30 秒版本**：
> "针对只有 RS485 能力的存量设备，我做了一套边缘采集系统：自制多传感器节点把振动/温湿度封装成标准 Modbus RTU 寄存器，网关主站在单总线上做确定性轮询、超时预算与故障隔离，数据经 MQTT 上云。节点侧用时域 RMS 做设备状态判定（运行/停机/异常），实测单从机掉线不影响其余从机数据新鲜度，断网 1 小时补传完整率 100%。"

**深挖题清单（每题必须能答 2 分钟）**：
1. 为什么选振动监测这个场景？（市场 + 传感器匹配 + 可演示）
2. 振动强度为什么用 RMS 而不是峰值/FFT？（时域 RMS 对周期性冲击不敏感、计算量 O(1) 窗口、F103 无 FPU 也够；FFT 对当前问题是过度设计——主动说出"不做什么"是加分项）
3. 阈值依据？（基线自学习 + 手动覆盖寄存器，见 1.3）
4. 误报怎么防？（连续 3 次 + 持续 2s；串联校赛连续帧确认经验）
5. 为什么工程量计算放节点不放网关？（见 1.3 三条）
6. 传感器坏了怎么办？（错误码寄存器 + 初始化降级 + 主站超时预算跳过，三层兜底）
7. 和买一个现成振动变送器有什么区别？（协议栈自主可控、成本、本项目考点在网关不在传感器——引用采购清单第 6 节降级话术）
8. 这个方案的天花板在哪？（MPU6050 带宽/量化精度有限，工业级要换 IEPE 传感器——诚实回答是加分项）

### 2.2 选型纪律（三条铁律）

1. **不在表内的器件不买、不写驱动**——想买的先写进冷冻区。
2. **每个器件只有一个角色**（MPU6050 的振动+倾角是同一物理量的两个指标，不算双角色）。
3. **升级必须先进冷冻区评审**，评审标准只有一条：它推进哪个里程碑验收？

### 3.2 里程碑验收表（每个里程碑只有一个验收动作）

对应主档卡 P0–P3，竞赛前完成 M1–M4。

| # | 里程碑 | 唯一验收动作 |
|---|---|---|
| M1 | 0x02 节点收口 | Modbus Poll 读 0x02，槽1/槽2/状态区全部为真实值（含 RMS 与状态位） |

## 5. 偏移警报清单（自检；任一命中 → 停手，回看本文件，想法进冷冻区）

1. 买了/接了 BOM 表外的器件；
