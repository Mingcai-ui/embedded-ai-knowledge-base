## 二、词汇频率分析（技能关键词）

### 2.1 MCU 方向（N=15）——核心技能频率

| 技能 | 出现次数 | 覆盖率 | 结论 |
|------|---------|--------|------|
| C 语言 | 15 | 100% | 绝对硬通货，无 C 不成岗 |
| STM32 | 13 | 87% | MCU 方向事实标准 |
| I2C | 13 | 87% | 外设三件套之一 |
| SPI | 12 | 80% | 外设三件套之一 |
| FreeRTOS | 11 | 73% | RTOS 绝对主流 |
| UART | 11 | 73% | 外设三件套之一 |
| 调试工具（示波器/逻辑分析仪/JTAG/SWD） | 8 | 53% | 中高级岗分水岭 |
| Keil | 7 | 47% | 主流 IDE |
| 传感器驱动 | 5 | 33% | |
| 数电/模电/原理图 | 5 | 33% | 软硬协同要求 |
| MQTT | 5 | 33% | 物联网岗专属 |
| OTA/Bootloader/IAP | 5 | 33% | 进阶能力 |
| CAN | 4 | 27% | 工控/汽车岗 |
| CubeMX 生态 | 4 | 27% | 崛起中的工具链 |
| IAR | 4 | 27% | 与 Keil 并列 |
| 低功耗 | 4 | 27% | 物联网岗 |
| PID/电机/运动控制 | 4 | 27% | 机器人/电机岗 |
| RT-Thread | 5 | 33% | 国产 RTOS 第二梯队 |
| uC/OS | 4 | 27% | 老牌 RTOS |
| 状态机 | 2 | 13% | 工程能力细节 |
| Linux（MCU 岗附带要求） | 3 | 20% | 双栈趋势 |

### 2.2 关键结论

1. **「STM32 + C + 外设三件套(UART/I2C/SPI)」构成 MCU 岗位的基本盘**，覆盖率普遍 ≥ 73%。
2. **FreeRTOS 在 RTOS 里断层领先**（73%），远高于 RT-Thread（33%）与 uC/OS（27%）。
3. **调试工具是「初级 → 中高级」的分界线**：初级岗不要求，中高级岗几乎必提（示波器、逻辑分析仪、JTAG/SWD、HardFault 分析）。
4. **Keil 仍是主流 IDE（47%）**，但 CubeMX/HAL 库生态（27%）明显在上升，二者是「任选其一」而非「必须同时」。

## 三、组合能力分析（共现 / 技能包）

> 单看频率会漏掉最重要的事实：**技能不是散点，而是成套出现**。下面是在同一条 JD 里反复成对/成组出现的能力组合。

### 3.1 核心共现关系（MCU 方向 N=15）

| 组合 | 共现次数 | 解读 |
|------|---------|------|
| STM32 × C | 13/15 | 最强绑定，几乎 100% |
| STM32 × FreeRTOS | 12/15 | 有 RTOS 的岗几乎都是 STM32 |
| 外设三件套(UART/I2C/SPI) × STM32 | 11/15 | 外设能力从不单独考核 |
| FreeRTOS × 外设驱动 | 11/15 | RTOS 岗必配外设开发 |
| Keil × CubeMX | 4/15 | 工具链「任选其一」，非同时要求 |
| 调试工具 × OTA/Bootloader | 4/15 | 中高级岗的标志组合 |
| MQTT × 无线(BLE/WiFi/LoRa) × 低功耗 | 5/15 | 物联网岗专属技能包 |

### 3.2 六类「技能包」（市场期望的能力组合）

| 技能包 | 组成 | 对应岗位画像 |
|--------|------|-------------|
| **① 单片机基本盘** | STM32 + C + 外设(UART/I2C/SPI) + Keil/CubeMX | 入门嵌入式软件岗 |
| **② RTOS 进阶** | 基本盘 + FreeRTOS + 任务/信号量/消息队列 + 中断 | 中级嵌入式岗 |
| **③ 调试能力** | 示波器 + 逻辑分析仪 + JTAG/SWD + HardFault 分析 | 中高级、量产岗 |
| **④ 物联网化** | 基本盘 + MQTT + BLE/WiFi/LoRa + 低功耗 + OTA | 智能硬件/物联网终端 |
| **⑤ 工业协议** | 基本盘 + Modbus(RTU/TCP) + RS485 + CAN | 工控/网关/仪表 |
| **⑥ Linux 双栈** | STM32 + Linux 驱动/BSP + C/C++ | 高薪进阶方向 |
| **⑦ AI 工具素养（新兴）** | 嵌入式 C + AI 辅助编码(Claude/Cursor/Copilot) + AI 辅助评审/定位 | 2026 新趋势 |
| **⑧ 边缘 AI** | C++ + Linux + 推理框架(ONNX/TFLite/NCNN/TensorRT) + 量化/剪枝 + NPU 异构 | 独立高薪赛道 |

### 3.3 边缘 AI 方向独立特征（N=5）

与 MCU 岗技能几乎不重叠，是一条**独立赛道**：

| 技能 | 出现次数 | 备注 |
|------|---------|------|
| C++（含 C++17 现代特性） | 5/5 | 比 C 更硬性 |
| Linux 环境开发 | 4/5 | 标配 |
| 推理框架（ONNX/TFLite/NCNN/MNN/TensorRT/QNN/RKNN） | 3/5 | 至少 2 种 |
| 量化/剪枝/蒸馏（PTQ/QAT/INT8/INT4/FP16） | 3/5 | 核心能力 |
| 异构计算（NPU/GPU/DSP） | 2/5 | 芯片平台相关 |
| LLM/vLLM/LoRA | 2/5 | 大模型端侧新需求 |
| CV/YOLO 目标检测 | 3/5 | 视觉为主 |
| PyTorch/TensorFlow | 2/5 | 训练框架 |

## 四、给千问模型的蒸馏要点（可直接作为 prompt 素材）

1. **市场对单片机岗的期望是「收敛」的**：STM32 + C + 外设三件套是硬门槛，不是加分项。
2. **FreeRTOS 是 RTOS 的唯一主流选择**，学习/项目优先级应远高于 uC/OS、RT-Thread。
3. **调试能力是晋升分水岭**，项目里应体现示波器/逻辑分析仪/JTAG/HardFault 实战。
4. **物联网终端岗 = MCU 基本盘 + MQTT + 无线 + 低功耗 + OTA**，这是「嵌入式物联网终端」标签的完整拼图。
5. **AI 工具素养已进入 JD 硬性要求**（如猎聘「加中准源」岗位明确要求 Claude/Cursor/Copilot 实战），且是 2026 年的扩散趋势。
6. **边缘 AI 是独立赛道**：C++ + Linux + 推理框架 + 量化剪枝 + 异构计算，与 MCU 技能正交，可作为差异化标签（对应 K230 边缘 AI）。
7. **工业网关岗位**强调 Modbus/RS485/CAN，与「Modbus 边缘采集网关」项目方向高度吻合。

## 六、结论一句话

**单片机岗的竞争是「收敛的硬门槛 + 成套的技能包」**：基本盘（STM32+C+外设）人人都会，真正的差异化来自「调试能力」「物联网协议栈」「Linux 双栈」「边缘 AI」这四条升级路线——而「AI 工具素养」正从加分项变成硬性要求，这与你正在做的项目方向直接相关。
