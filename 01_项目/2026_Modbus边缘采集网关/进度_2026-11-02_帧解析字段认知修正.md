## 一、本轮涉及的内容

在口述 P0-A 数据链路时，对「帧解析产物的四个字段（addr / func / data / status）」与「CRC 字节序」做出的判断被逐条纠正。链路本身（发送端无 3.5T、接收端断帧后交出 `{buf,len,ts}`、解析器只吃 `{buf,len}`）判断正确。

## 二、能力判定

| 项 | 判定 | 依据 |
|---|---|---|
| 3.5T 不向帧内追加字节（长度/时间戳是本机元数据，不上线缆） | **已掌握** | 前一环节纠正后能自行复述，并正确推出"发送端无 3.5T" |
| ③断帧 与 ④解析 是两个状态机 | **半懂** | 仍用"接收状态机做解析"的混称，职责边界需再固化 |
| addr 需判（地址不匹配静默丢，出 ADDR_MISMATCH） | **未验证** | 本轮判断为"不用判断"，被纠正后才接受 |
| func 需判 bit7（决定第 3 字节是 byte_count 还是异常码） | **未验证** | 同上；未自行推出"func 是字段布局开关" |
| CRC 需"从 data 中拆分出来" | **认知修正** | 实际不需要拆：边界由 byte_count 定，校验靠整帧回灌=0 |
| status 的含义 | **认知修正** | 曾认为 status 是 CRC 计算结果值；实为状态枚举 |
| CRC 字节序（低字节先） | **回退** | 2026-11-01 已修正并写入 [[进度_CRC16_Modbus_完整记录]] 第 8 节，本轮又说"高位在前" |
| 用 crc_recv 与 mb_crc16(buf,n-2) 互校 | 新增 | 本轮给出的自检手段，尚未实操 |

**整体**：链路层概念已立住，协议层字段级理解尚未建立。④ 目标为 L3，当前 0/6 组向量验证。

### 短板

- **字节序记忆不稳**：低字节先已在笔记中修正过一次，仍会回退。这是"记住结论但未形成反射"，需在每次写 CRC 相关代码时强制过一遍自检。
- **把"字段是否存在"与"字段是否需判断"混为一谈**：addr/func 被当成"解析出来顺手带上"的字段，未意识到它们是**控制流开关**。
- **倾向用"数值"解释状态**：把 status 理解成 CRC 值，反映对"状态机输出应为判定结果而非中间量"这一设计范式尚不熟。
- **状态机职责边界易混**：③ 与 ④ 的分工需再用一句话固化——③ 管"帧在哪结束"，④ 管"帧里是什么"。
