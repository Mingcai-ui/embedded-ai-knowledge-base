# 寄存器模型、两级寻址与溢出边界（2026-11-08）

> 本次围绕 02 号地址（本机 DHT11 从机）落地，澄清了几处此前含糊或缺失的认知。已有教程（[[教程_2026-11-03_Modbus零基础详解]] 的帧拆解/数据区/3.5T）已覆盖的内容不在此重复。

## 一、学了什么

1. **两级寻址**（此前把「设备号」和「数据编号」混为一谈）：一帧里有两个互不相关的地址 —— 从机地址（选哪台设备）与寄存器起始地址（选设备内第几个数据点）。每个从机有独立的地址空间、各自从 0 编号，**不存在「02 号设备的寄存器从 2 开始」**。类比：从机地址 = 楼栋号，寄存器地址 = 房号。

2. **寄存器 = uint16_t 数组**：协议的「保持寄存器」落到 C 就是 `uint16_t arr[N]`，数组下标 = 寄存器地址（0-based），组包用 `arr[RegAddress + i]` 直接取数。用数组而非散变量的理由：让「任意起始地址 + 任意数量」的读请求都走同一段代码，加参数只增元素、不改逻辑。

3. **寄存器 16 位上限与两种「溢出」**（新知识，教程未覆盖）：
   - 单寄存器固定 16 位：uint16 = 0~65535，int16 = −32768~32767。
   - **值溢出 = 静默截断**（安全但值错）：`uint16_t r = 70000;` → 4464，编译器不报错。温湿度 ×10 最大才 1000，远碰不到上限。
   - **下标越界 = 内存踩踏**（危险）：`arr[10] = x` 写数组外，与值溢出本质不同。`makePacket_03` 用 `(uint32_t)RegAddress + NumberOfReg > N` 挡外部越界，注意要用 uint32_t 相加防回绕。
   - 32 位数据（时间戳/浮点/累计量）拆两个寄存器；**寄存器内部字节序协议定（大端），跨寄存器字序厂商自定义** —— 接第三方 32 位数据读到大数，先怀疑字序反了。

4. **Modicon 传统编号**：手册写「40001」= 保持寄存器第 1 个，协议地址是 0（`40001−40001=0`）。接 01 号变送器看手册时必踩。

5. **拆包/粘包的本质**：Modbus RTU 无长度字段，帧边界全靠 3.5T 静默。本工程 5ms 判帧：115200 下余量 16 倍（9600 下仅 1.37 倍）。拆包/粘包都不「重组」，只会被长度/CRC 挡住后丢弃，靠主站超时重发恢复。抗拆包唯一办法是**长度字段提前判帧**（功能码可算出帧长：0x03 固定 8、0x10 = 9+字节数）。

6. **缓冲区边界**：`BUFFERSIZE=255` 恰好 = 0x10 写满 123 寄存器的 ADU 上限；**不可升 256**，否则 uint8_t 计数器回绕成 0、整帧被当空帧丢弃。255 字节合法帧 vs 超长帧，主循环只看得到 `len=255`，靠中断置 `frameOverflow_PC` 区分。

7. **工具认知**：Git 分支没有「介绍文档」字段，用 Draft PR 承载；Release 打在 tag 上、与分支无关。
