# 低功耗 LoRa 无线采集节点 · 主档卡

> **定位**：第二简历项目（完整型），2027.1–2027.6 实施。
> **时间线（2026-10-28 审查修正）**：暑期实习投递与面试窗口在 **2027 年 3–6 月**，原「2027.7 前收口」对求职无效。里程碑重排——**2027-03 前必须出现「P1 功耗账本 + 实测波形」**，P2/P3 可延后。
> 与主线项目的关系：[[Modbus边缘采集网关-主档卡]] 是**深度型**项目（协议栈 + 高可靠数据链路），本项目是**完整型**项目（需求 → 硬件 → 固件 → 实测 → 选型报告）。P2 阶段两者串联成「无线节点 → LoRa/RS485 → 网关 → MQTT 云」的真实工业拓扑，不是两个孤岛。
> 立项依据：2026-10-27 招聘网站 JD 调研（"低功耗"为物联网岗高频词，实测功耗数据是应届生简历稀缺硬货）。

## 一句话目标

做一台**电池供电、月级续航、睡眠电流微安级**的野外传感节点：DHT11 采集 → LoRa 无线上报 → 接入 Modbus 网关上云，每一 uA 花在哪都能讲清并给出实测账本。

## 系统拓扑

```
[节点1] F103 + DHT11 + LoRa模组 ─┐  (睡眠→RTC唤醒→采集→发送→睡眠)
[节点2] F103 + 传感器 + LoRa模组 ─┤
                                 │ 433MHz 无线（自定义帧 + ACK/重传）
                    ┌────────────▼─────────────┐
                    │ LoRa-RS485 DTU（转换模块） │
                    └────────────┬─────────────┘
                                 │ RS485 / Modbus RTU
                    ┌────────────▼─────────────┐
                    │ Modbus 边缘采集网关（项目一）│
                    │ → MQTT → 云平台可视化      │
                    └──────────────────────────┘

[P3 可选变体] 节点 + Air780E(4G/NB) → MQTT 直连云（与 LoRa 方案做实测对比）
```

## 技术硬核（必须手写并吃透）

1. **低功耗状态机**：唤醒 → 采集 → 发射 → 休眠 主循环，Stop/Standby/Sleep 三档的电流、唤醒源、RAM 保持差异（注意 Stop 唤醒后时钟回落 HSI 8MHz、需重配 PLL；Standby 唤醒等于复位）
2. **RTC + LSE**：32.768kHz 晶振起振确认（蓝pill 板 LSE 常见不起振，是 P1 第一坑），LSI 兜底方案
3. **自定义无线帧协议**：帧头 + 节点地址 + 载荷 + 校验 + ACK/重传，迁移 [[UART自定义帧协议_接收状态机与防误识别]] 的连续帧确认经验，补上它遗留的"帧间超时复位"
4. **功耗预算表**：各状态电流 × 占空比 → 平均电流 → 续航推算，全表用实测值不用手册典型值
5. **LoRa 参数权衡**：扩频因子 SF / 带宽 BW / 空中速率与距离、功耗、占空时间的三角关系

## 面试防御题清单（逐行追问时必须答得出）

- Stop / Standby / Sleep 电流各是多少？唤醒源分别有哪些？唤醒后 RAM 内容还在吗？
- RTC 为什么用 LSE 不用 LSI？LSE 不起振你怎么排查、怎么兜底？
- uA 级电流怎么测？万用表电流档的 burden voltage（负担电压）问题是什么，怎么规避？
- 电池从 4.2V 放到 3.3V，LDO 还能稳住吗？压差（dropout）怎么算？
- SF 调大一档，距离、功耗、空中时间各怎么变？
- 为什么选 LoRa 不选 NB-IoT / WiFi / BLE？（要能默画四维对比表，P3 有实测数据支撑）
- 两个节点同时发送会怎样？你的信道策略是什么？
- 续航推算的公式和每一行的数据来源？
- 为什么「野外低功耗节点」第一传感器不用 DHT11？（±2℃/±5%RH、采样 ≥1s、模块版带 LED 待机 mA 级——必须换 SHT30/SHT20）
- 节点 → LoRa → DTU → RS485 → 网关 → WiFi → 云共 4 次协议转换，为什么不直接做 LoRa 网关？（答辩话术见「架构冗余」）

## 遗留 / 边界说明

- **CAN 空白不由本项目覆盖**（2026-11-01 方向决策更新：**放弃学习 CAN 总线**，精力转向 SPI / I2C；同时**放弃 Linux**）。CAN 优先级不再提级，第二项目锁定低功耗物联网方向。
- 本项目**不引入 FreeRTOS**（单任务低功耗主循环裸机即可，故意保持与网关项目的 RTOS 叙事不重复——面试时两项目一个讲 RTOS 多任务、一个讲裸机低功耗，覆盖面互补）。

## 排坑记录

- [ ] （待填）LSE 32.768kHz 晶振不起振 / RTC 走时不准
- [ ] （待填）核心板板载 LDO 静态电流与电源 LED 导致睡眠电流下不去（需割断 LED 或换低压差 LDO）

- [ ] **Standby 唤醒 = 复位**：RAM 丢失，与 Stop 是两种程序设计思路，不能混用
- [ ] **唤醒瞬间去耦电容充电电流**：会造成「平均电流算得漂亮、实测偏高」，实测时需识别并解释

## 架构冗余答辩话术（2026-10-28 审查补）

节点 → LoRa → DTU → RS485 → 网关 → WiFi → 云共 4 次协议转换，面试必问「为什么不直接做 LoRa 网关」。

**标准答案**：DTU 是工业现场存量改造的现实路径——无线节点接入**已有 RS485 总线**，复用网关是刻意的**系统复用**而非能力缺失。不是「多此一举」，是「不推翻存量布线」。
