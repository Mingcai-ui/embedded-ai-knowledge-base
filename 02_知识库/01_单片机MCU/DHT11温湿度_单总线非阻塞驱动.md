# DHT11 温湿度传感器：单总线非阻塞驱动（详细版）

> 来源：为本项目（第六届人工智能设计大赛 · STM32F103C8T6 接收数据测试）新写的驱动
> 本文为「代码介绍」详细版，对应 `dht11.c / dht11.h`（工程 `Core/Src`、`Core/Inc`）。

## 1. 模块概述

**一句话功能**：通过单总线读取 DHT11 温湿度，内部用状态机调度时序，非阻塞返回数据。

**设计模式**：有限状态机（FSM，毫秒级）+ `HAL_GetTick()` 非阻塞 + DWT 微秒计时（微秒级紧贴时序读取）

**复杂度**：★★★★☆

读者初次看时**只需理解 4 个对外 API**，内部时序层是为「可移植 + 非阻塞」服务，可后面再啃。

## 2. 硬件信息

**引脚连接**（PA11，已确认）：

| 设备 | 端口 | 引脚 | 运行时模式 | 有效电平 | 备注 |
|---|---|---|---|---|---|
| DHT11 数据线 | GPIOA | PA11 = `DHT11_GPIO_PIN` | 输出推挽 ⇄ 输入+上拉 动态切换 | 低触发 | 单总线，双向 |

**电路接法**：
```
3.3V ─┐
      ├─[建议 4.7k~10k 上拉]─┐
DHT11 DATA ─────────────────┤  GPIO_PIN_11 (PA11)
DHT11 GND ────────────────── GND
DHT11 VDD ───────────── 3.3V
```

> ⚠️ **上拉建议**：DHT11 数据线需要一个约 **4.7k~10k 上拉**才能可靠回高。驱动内部用了 STM32 内部上拉（约 30~50k），多数模块能跑，但**个别 DHT11 模块时序偏急会读数失败**。模块板自带上拉则无需外加；上板不稳时优先外接 4.7k。

**电气特性**：单总线半双工；主机拉低起始，从机主动应答；空闲时数据线被上拉拉高。

## 3. 为什么单总线要分层

DHT11 只有一根数据线，时序分**两类**，处理方式完全不同：

- **毫秒级**（起始信号拉低 ≥18ms、两次读取间隔 ≥1s）：`HAL_GetTick()` + 状态机 → **非阻塞**，主循环不被卡住。
- **微秒级**（应答 80us + 40 位数据，每 bit 高电平宽 26~70us 区分 0/1）：必须紧贴时序读取，`HAL_Delay(ms)` 精度不够，用 **DWT 周期计数器**做 us 计时 → **集中一次阻塞约 4ms，每秒一次**。

**结论**：耗时长的部分非阻塞，真正必须紧贴的微秒读取只有约 4ms 且每秒一次，这是单总线传感器的合理折中。

## 5. 接口函数

| 函数 | 调用频率 | 作用 |
| --- | --- | --- |
| `DHT11_Init(&dht)` | 初始化一次 | 复位状态机、使能 DWT、配置 PA11 为输入 |
| `DHT11_Handler(&dht)` | 主循环每次 | **必须持续调用**，内部按状态机调度，返回 `DHT11_OK/BUSY/ERROR` |
| `DHT11_GetTemp(&dht)` | 读取成功后 | 返回 float 温度（℃） |
| `DHT11_GetHumi(&dht)` | 读取成功后 | 返回 float 湿度（%RH） |

### 5.1 `DHT11_Handler`（主循环每次）
```c
DHT11_Status DHT11_Handler(DHT11_Handle_t *dht);
```
- **作用**：非阻塞驱动整体节奏（等待间隔 → 拉低起始 → 释放并读取），`DHT11_OK` 仅当本次调用刚完成一次成功读取时返回。
- **位置**：**必须放 `while(1)` 持续调用**，驱动自己管理 2s 间隔，主循环不许 `HAL_Delay` 拦路。
- **返回值**：`DHT11_BUSY`(0) / `DHT11_OK`(1) / `DHT11_ERROR`(2)。

## 6. 数据结构

### `DHT11_Handle_t`（约 12 字节）
```c
typedef struct {
    uint8_t  humidity_int;   // 湿度整数 (%RH)
    uint8_t  humidity_dec;   // 湿度小数
    int8_t   temp_int;       // 温度整数 (°C，有符号)
    uint8_t  temp_dec;       // 温度小数
    // === 内部状态，用户勿动 ===
    uint8_t  state;          // 0=等待间隔，1=起始信号（含读取）
    uint32_t last_tick;      // 最近时间戳(ms)
} DHT11_Handle_t;
```
- **生命周期**：在 `main.c` 定义全局变量 `DHT11_Handle_t dht;`。

## 7. 关键宏定义（可移植配置区，换引脚只改这里）

| 宏 | 默认 | 含义 | 硬件相关性 |
|---|---|---|---|
| `DHT11_GPIO_PORT` / `DHT11_GPIO_PIN` | `GPIOA` / `GPIO_PIN_11` | 数据引脚 | **换引脚要改** |
| `DHT11_START_LOW_MS` | `20` | 起始信号拉低时长(ms) | 小于 18 会失败 |
| `DHT11_READ_INTERVAL_MS` | `2000` | 两次读取最小间隔 | 小于 1000 违例 |
| `DHT11_BIT_1_US` | `40` | 判 bit=1 的高电平阈值(us) | 视 DHT11 批次微调 |
| `DHT11_LEVEL_TIMEOUT_US` | `200` | 等待电平最长期限(us) | 通用 |

> 宏全大写 `XXX_YYY`，用 `#ifndef` 包裹，允许编译器/用户工程覆盖，提升可移植性。

## 8. 调用流程（核心，体现非阻塞）

```c
#include "dht11.h"
DHT11_Handle_t dht;

// ① 初始化（main 开头，MX_GPIO_Init 之后）
DHT11_Init(&dht);

// ② 主循环（while(1)）——注意去掉 HAL_Delay(100)！
while (1) {
    Button_Handler(&Key1);                 // 按键仍非阻塞轮询
    if (DHT11_Handler(&dht) == DHT11_OK) { // 每 ~2s 返回一次 OK
        float t = DHT11_GetTemp(&dht);
        float h = DHT11_GetHumi(&dht);
        OLED_ShowFloatNum(5, 0, t, 3, 1, OLED_8X16);
        OLED_ShowFloatNum(5, 1, h, 3, 1, OLED_8X16);
        OLED_Update();
    }
}
```

## 9. 依赖关系

- **HAL 函数**：`HAL_GPIO_Init`（配输入/输出）、`HAL_GPIO_WritePin`（BSRR）、`HAL_GPIO_ReadPin`（IDR）、`HAL_GetTick`（SysTick）。
- **非 HAL 依赖**：`CoreDebug->DEMCR`、`DWT->CTRL`、`DWT->CYCCNT`（Cortex-M3 内核调试单元）、`SystemCoreClock`。
- **被谁调用**：`main.c`。
- **调用谁**：无（只产生结果数据），如需显示由用户接 OLED 等。

## 10. 底层关键点（进阶）

| 依赖 | 作用 | 本模块使用 |
|---|---|---|
| `DWT->CYCCNT` | 内核周期计数器，主频一个周期 +1 | 除以 `SystemCoreClock/1e6` 得微秒，做紧贴时序 |
| `CoreDebug->DEMCR |= TRCENA` | 放开 DWT 访问 | `DHT11_DWT_Enable()` 里执行一次 |
| `GPIO CRH/B` | 引脚模式/速度 | `MX_GPIO_Init` → 驱动运行时切换输入/输出 |
| `GPIO IDR` | 读引脚实际电平 | 测量 DHT11 波形宽度 |
| `GPIO BSRR` | 原子置/清位 | 拉低起始信号 |

- **us 时间戳翻转**：`DWT->CYCCNT` 会从 UINT32_MAX 翻回 0，但所有调用都用「当前值 - 起始值」的 uint32 减法判间隔，翻转被自动处理，无需特殊处理。
- **微秒超时兜底**：`DHT11_WaitLevel / MeasureHighUs` 都带超时，DHT11 掉线不会死循环。

## 11. 设计要点

- **A 层隔绝 HAL**：所有 GPIO 读写/输入输出切换封装成内部函数，业务层不碰 HAL，换芯片只动一处。
- **非阻塞折中**：18ms 起始 + 2s 间隔非阻塞；仅约 4ms 微秒读取阻塞，每秒一次。比「`HAL_Delay(18)` 哈一个回合」的教程版更专业。
- **bit 判定阈值**：DHT11 '0' 高电平 26~28us、'1' 约 70us，取阈值 40us 用测量时长区分，比数循环次数稳定。
- **运行时配引脚**：`DHT11_Init` 里自开关 GPIOA 时钟并配输入，因此**无需改 CubeMX**，PA11 空闲即可用。

## 12. 测试方法

**验证步骤**：
1. 编译无错误无警告（Keil 记得把 `dht11.c` 加入工程）。
2. 下载运行，观察 OLED 显示温度/湿度（2s 间隔刷新）。
3. 用手捂 / 哈气，观察温湿度变化。
4. 断开 DHT11，确认程序不死机（超时兜底返回 `DHT11_ERROR`）。

**预期现象**：温度随体温缓慢上升；湿度在哈气时明显上升；数值约 2s 更新一次且能稳定。

**常见故障排查**：

| 现象 | 可能原因 | 解决方案 |
|---|---|---|
| 一直 `DHT11_ERROR` | 数据线上拉不足；引脚接错 | 外接 4.7k 上拉；核对 `DHT11_GPIO_PIN` |
| 首次能读后续失败 | 间隔太短 | 保持 `DHT11_READ_INTERVAL_MS ≥ 2000` |
| 读数抖动大 | 主循环被 `HAL_Delay` 拖延、时序拉长 | 去掉主循环阻塞延时 |
| 温度为负出问题 | 有符号转错 | 确认 `temp_int` 用 `(int8_t)` 强转 |
