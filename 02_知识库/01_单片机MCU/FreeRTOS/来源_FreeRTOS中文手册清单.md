# FreeRTOS 中文手册与教程清单

> 场景：英语是短板，需要中文资料；平台 STM32F103C8T6 / CubeMX + CMSIS-OS2 封装 / VS Code + EIDE。
> **需求锚点：要能查 API 和 API 返回值。** 下文按「查返回值 → 学原理 → 做实验」分工，不重复。

## 一、FreeRTOS 官方简体中文 API 参考（★ 首选，唯一覆盖全 + 最新）

- **入口**：https://www.freertos.org/zh-cn-cmn-s/Documentation/02-Kernel/04-API-references
- **单页示例**：https://www.freertos.org/zh-cn-cmn-s/Documentation/02-Kernel/04-API-references/01-Task-creation/01-xTaskCreate
- **性质**：AWS 官方给出的简体中文版 API 参考，2026-10 仍在更新
- **覆盖**：任务创建 / 任务控制 / 任务工具 / 队列 / 信号量 / 互斥量 / 软件定时器 / 事件组 / 任务通知 / 流缓冲 / 消息缓冲 / MPU 专用 等全部分类
- **每页固定四段**：函数原型（含头文件）→ **参数逐条解释** → **返回值** → 可运行的示例代码
- **定位**：**查返回值就查这里。** 例：`xTaskCreate` 返回 `pdPASS` 或 `errCOULD_NOT_ALLOCATE_REQUIRED_MEMORY`，页面上写得明明白白
- **优点**：覆盖最新 API（静态创建、流缓冲、任务通知都在），与 V10.3.1 基本对齐
- **缺点**：机器翻译，个别句子生硬，但技术含义准确；链接路径全英文，需从上级目录点进去

## 二、野火《FreeRTOS 内核实现与应用开发实战》中文文档站（★ 中文可读性最好）

- **入口**：https://doc.embedfire.com/rtos/freertos/zh/latest/index.html
- **性质**：人工编写的中文教材，Sphinx 在线阅读站，基于 STM32
- **两部分结构**：
  - **从 0 到 1 写内核**（列表与列表项、任务定义与切换、临界段、空闲任务与阻塞延时、多优先级、延时列表、时间片）—— 想吃透调度器原理看这里，比任何翻译版都清楚
  - **应用开发**（任务管理 / 消息队列 / 信号量 / 互斥量 / 事件 / 软件定时器）
- **API 呈现方式**：每个函数一张表 —— 函数原型 / 功能 / 参数 / **返回值**，再附源码分析
- **定位**：**中文讲解 + API 速查二合一**，术语统一、无翻译腔
- **对应进度**：第 7 章信号量、第 8 章互斥量 → 路线第 7 周；第 10 章软件定时器 → 任务C

## 三、《掌握 FreeRTOS 实时内核》中文版（学原理）

- **链接**：http://freertoskernel.asicfans.com
- **原名**：*Mastering the FreeRTOS Real Time Kernel — A Hands-On Tutorial Guide*（Richard Barry）
- **覆盖**：RTOS 概念、任务状态机、调度策略、优先级、队列与信号量内部机制、内存管理方案
- **定位**：回答"为什么这么设计"，不是"函数怎么写"
- **注意**：对应 2016-12 副本，**不含 V9/V10 的静态创建、低功耗 Tickless**

## 五、⚠️ 勘误：`freertos.asicfans.com` 是残卷，别用

- 原以为它是官方 API 参考的中文全译，**实测只有 1/9 有内容**。
- 实测各章 markdown 原文长度：

| 章节 | 长度 | 状态 |
| --- | --- | --- |
| 任务和调度程序 API | 28,719 | ✅ 唯一完整 |
| 队列 / 信号量 / 软件定时器 / 事件组 / 内核配置 / 流缓冲 / 消息缓冲 | 各约 280 | ❌ 只有标题，正文为空 |
| 附录 1（数据类型与命名） | 1,832 | 部分可用 |

- 结论：**只能查到任务类 API，队列和信号量全空**。而我下一步（信号量、软件定时器、任务通知）恰好全在空缺里。已被上面第一、二项替代。

## 关键要点

1. **全是原生 API**（`xTaskCreate` / `vTaskDelay` / `xQueueSend`），我写的是 CMSIS-OS2（`osThreadNew` / `osDelay` / `osMessageQueuePut`）。转换查自己的 [[CMSIS-RTOS2函数速查表-STM32CubeMX版]] **第 11 章对照总表**。
2. **返回值映射**：CMSIS-OS2 把 `pdPASS/pdFAIL` 包成了 `osOK` / `osErrorXxx` 枚举。查原生返回值时，同步看速查表该函数对应 `osStatus_t` 的定义，别混用。
3. **版本差**：野火 / 正点原子资料多为 V8/V9，我用 10.3.1。基础 API 无变化；差异在 V9 起的静态创建和 V10 的增补。官方中文站（第一项）是最新版，优先以它为准。
4. **RAM 陷阱**：正点原子例程跑在 ZET6（64KB RAM），C8T6 只有 **20KB**。`configTOTAL_HEAP_SIZE` 和任务栈**不能照抄**。C8T6 建议：堆 6–10KB，任务栈从 128 字（512 字节）起。

## 与我的关联 / 启发

- 查返回值的最佳路径固定为：**官方中文 API 参考**（准 + 全）→ 不懂为什么 → **野火对应章**（中文讲透）→ 要动手 → **正点原子例程**（砍资源后复现）。
- 「半懂」档那两点（`osMessageQueuePut` 的 `osWaitForever` 阻塞语义、队列字节数静默截断），野火「消息队列」章有源码级解释，比速查表更能讲清为什么。
