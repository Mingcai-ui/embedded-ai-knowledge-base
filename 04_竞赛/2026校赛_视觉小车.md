# 2026 校赛 · 扑克牌识别视觉小车

## 任务目标

双主控视觉循迹小车，两种工作模式：

- **模式 1（循迹）**：8 路灰度循迹跑 2 圈，第 1 圈完成时蜂鸣器响 1 秒，2 圈自动停车。
- **模式 2（识别）**：循迹跑 1 圈的同时，K230 识别赛道旁的扑克牌，STM32 记录并 OLED 显示识别历史（4 张/行 × 3 行）。

按键 KEY1 切模式，KEY2 启动；启动时清空牌历史、复位编码器和 PID。

## 系统架构

```text
┌──────────────── K230 (CanMV/MicroPython) ─────────────────┐
│ 摄像头(1280×720 RGB888) → ai2d resize → kmodel 分类(54类) │
│          ↓ softmax 置信度过滤                              │
│ UART2 (TX=GPIO11) 115200                                  │
└──────────────────────┬─────────────────────────────────────┘
                  7字节帧 AA 55 花色 点数 校验和 0D 0A
                       ↓
┌──────────────────────┴─────────────────────────────────────┐
│ ┌──────────────── STM32F103C8T6 (最终版) ─────────────────┐ │
│ │ USART3(PB10/11) 单字节中断 → 状态机拼帧 → 校验和        │ │
│ │   → 连续2帧确认 → 去重 → 牌历史数组 → OLED 显示         │ │
│ │ 8路灰度 → 加权偏差 → 位置式PD → 差速 → 双电机(TIM2 PWM) │ │
│ │ TIM3 100μs 软件正交解码编码器 → 里程/圈数 → 停车控制    │ │
│ └─────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────┘
```

## 版本演进：基础版 → AI 完善最终版

基础版为**纯手搓**代码（循迹 + OLED 调试显示 + MPU6050 角度环尝试），最终版是**基于基础代码与 AI 协作迭代**的校赛用车。关键演进：

| 项 | 基础版（手搓） | 最终版（AI 协作） | 变化原因 |
|---|---|---|---|
| 视觉通信 | 无 | USART3 + 帧协议 + 防误识别 | 接入 K230 扑克牌识别（赛题核心） |
| MPU6050 | I2C2 驱动 + 角度环（未用上） | 整个模块移除 | 硬件未装/方案弃用，减小体积 |
| 编码器采样 | TIM3 1ms，PB12/PB13 | TIM3 100μs，PB14/PB15 | 10 倍采样率防丢脉冲，引脚改板 |
| ENCODER_PPR | 5500 | 25160 | 换电机/减速比后实测重标 |
| PID 参数 | Kp=1.1, Kd=1.3, ±400 | Kp=2.3, Kd=2.8, ±600 | 提速后重调参 |
| 差速 | `PID.Out × 30`，限 ±400 | `PID.Out × 20`，差速上限=基速×0.8，单向截 0 | 弯道更稳，防原地转 |
| 状态机 | 上电即跑（无启动控制） | 按键启动/模式切换/蜂鸣器/圈数停车 | 比赛流程需要 |
| 调试 | OLED 显示原始状态 | UART 收发计数器 + K230 端诊断打印 | 排查"识别到但没收到"问题 |

**AI 协作开发的经验**：手搓基础版保证了对自己代码架构的完全掌控（模块划分、PID 骨架、编码器解码都是自己写的）；AI 迭代擅长的是补工程细节（帧状态机、防误识别去重、调试计数器、边界处理）。两者结合效率最高——先手搓跑通最小闭环，再让 AI 按需求逐条加固。

## 结论 / 复盘

**做得对的**：
1. 双主控解耦：视觉（Python 生态，迭代快）与控制（C/中断，实时性）各干各的，UART 帧协议是清晰边界——两个模块可以完全独立开发调试。
2. 协议层多重防护（帧头+校验和+连续帧确认+去重）实际比赛中零误记录。
3. 先手搓基础版再 AI 加固的路径，既保住了对代码的理解，又补齐了工程细节。

**待改进**：
1. 只有一个编码器测总里程，没有双轮测速——速度环未真正闭环，PID 实际只是位置（偏差）环。
2. 丢线策略简单（固定返回 -1），急弯可靠性依赖差速上限的经验值。
3. 接收状态机无帧间超时复位（详见通信笔记"已知坑"）。[[UART自定义帧协议_接收状态机与防误识别]]
