# 网关底层四项 · 施工与验收清单

> 项目：[[Modbus边缘采集网关-主档卡]]｜核心一：[[核心一_ModbusRTU协议栈与多机轮询-档卡]]
> 硬件在途，①②两项不需要板子就能做完。四项全过才允许发第一帧真报文。

**四个关卡是一条链**：①骨架 → ②CRC → ③3.5T 断帧 → ④帧解析状态机 → 才能联机。

## ① 工程骨架

**要达成的效果**：板子一上电，串口助手能看到日志，说明时钟、串口、定时器、DMA 全部活着。

### CubeMX 设置

- [ ] RCC：HSE 8MHz → PLL ×9 = **72MHz**
- [ ] USART1：115200 8N1（人看的日志口）
- [ ] USART2：9600 8N1（RS485 数据口）
- [ ] USART2 → DMA：**RX 循环模式**（Circular，不是 Normal）
- [ ] USART2 开 **IDLE 中断**（`__HAL_UART_ENABLE_IT(&huart2, UART_IT_IDLE)`）
- [ ] TIM2：预分频 71 → **1µs 计数**
- [ ] 一个 GPIO 推挽输出，命名 `RS485_DE`，上电默认**低电平**

### 通过标准

串口助手能看到：`boot ok, clk=72MHz, tim2=1us`，且 1 秒打印一次心跳计数。

### 常见失败

| 现象 | 原因 |
|---|---|
| DMA 只收到第一批数据，之后不动 | DMA 配成了 Normal，没开 Circular |
| 一帧数据不完整就触发"收完" | 只开了 IDLE，没做 3.5T 二次判定（IDLE 只保证 ≥1 字符空闲） |
| 定时器一开就进中断 | **TIM4 是你的 HAL 时基，别拿来当 3.5T 计时**；用 TIM2 |
| 串口乱码 | PLL 没生效或波特率时钟源算错 |

## ② CRC16（必须手写，不许抄查表数组）

**要达成的效果**：给任意一段字节，算出的 CRC 与标准帧一字不差。

### 三条硬约束

1. 多项式 **0xA001**（是 0x8005 的逐位反转，不是字节交换）
2. 初值 **0xFFFF**（不是 0x0000）
3. 发送顺序 **低字节先、高字节后**

### 自测向量（全对才算过）

| 报文（不含 CRC） | CRC 值 | 实际发出的两个字节 |
|---|---|---|
| `01 03 00 00 00 0A` | 0xCDC5 | `C5 CD` |
| `01 03 00 00 00 02` | 0x0BC4 | `C4 0B` |
| `02 07`（Modbus 规范原文示例） | 0x1241 | `41 12` |

> 三组都用在线 CRC-16/Modbus 工具再核一遍再写进代码。**帧尾看到 "C4 0B" 是低字节在前，别把它当成 0xC40B。**

### 通过标准

- 3 组向量全对
- 负例：把任一字节改掉，CRC 必须变
- 反向校验：把整帧（含 CRC）丢进同一个函数，结果应为 **0x0000**——这一招比单独拆出 CRC 比对更省事

### 常见失败

| 现象 | 原因 |
|---|---|
| 差 0xFFFF 或整体反了 | 初值写成 0x0000 |
| 完全算不对 | 用 0x8005 直接右移，忘了位反转成 0xA001 |
| 数值对但设备不认 | 高字节先发了 |

## ③ 3.5T 帧边界

**要达成的效果**：只吃「字节 + 到达时刻」，就能输出"这一帧结束了"的事件，不靠延时凑数。

### 时间常数（8N1，1 字符 = 11 bit）

| 波特率 | 1 字符 | T1.5 | T3.5 |
|---|---|---|---|
| 9600 | 1.146 ms | 1.72 ms | **4.01 ms** |
| 19200 | 0.573 ms | 0.86 ms | 2.00 ms |
| 115200 | 95.5 µs | 143 µs | 334 µs |

> 规范另有规定：**波特率 > 19200 时改用固定值** T1.5 = 750µs、T3.5 = 1.75ms。你现在跑 9600，按上表算即可，但代码里把常数写成可配置的。

### 算法骨架

```
IDLE 态：
  来一个字节 → 记 t0 = now，转 RX 态
RX 态：
  来一个字节 → 若 now - t_last > T3.5 → 上一帧结束（投递），本字节开新帧
              → 否则 t_last = now，继续攒
  定时器每 1ms 检查 → 若 now - t_last > T3.5 → 帧结束，回 IDLE
```

### 三选一的时间源（推荐 DWT）

| 方案 | 优点 | 缺点 |
|---|---|---|
| `DWT->CYCCNT` | 72MHz 下 13.9ns 精度，零外设占用，不加代码就有 | 需开 `DEMCR` 的 TRCENA |
| TIM2 1µs 计数 | 直观、好调试 | 占一个定时器 |
| 只靠 IDLE 中断 | 最简单 | **不够**：9600 下 IDLE 只等 1 个字符（1.15ms），判定不到 4ms，必须配定时器兜底 |

### 通过标准

- 喂 8 字节、间隔 1ms → 输出 **1 帧**
- 第 4、5 字节之间插 6ms 空隙 → 输出 **2 帧**
- 边界测试：间隔 4.0ms 判 1 帧、4.1ms 判 2 帧
- 帧结束事件里带着「本帧字节数 + 时间戳」

### 常见失败

| 现象 | 原因 |
|---|---|
| 两帧粘成一帧 | 用 `HAL_Delay` 或任务里轮询判帧，被别的任务挤掉了 |
| 一帧被切成两帧 | 阈值取了 3.5 个**字节数**而不是 3.5 个**字符时间**；或忘了 1 字符是 11 bit 不是 8 bit |
| 换波特率就崩 | 常数写死了没跟着波特率算 |

## ④ 帧解析状态机（核心一白板题，必须能徒手画）

**要达成的效果**：一帧字节进去，出来的是「解析好的数据」或「明确的错误码」，不允许"解析失败但没人知道为什么"。

### 状态划分

```
WAIT_ADDR → WAIT_FUNC → WAIT_LEN(仅 03/04) → WAIT_DATA×N → WAIT_CRC_LO → WAIT_CRC_HI → DONE
                              ↓ 功能码 bit7=1
                         异常帧路径（异常码在数据区第 1 字节）
```

### 六组测试向量（分支全走对才算过）

- [ ] 正常帧：`01 03 04 02 4C 00 BA xx xx`
- [ ] CRC 错：改末字节 → 报 CRC 错，不投递数据
- [ ] 地址不匹配：`02 ...` → 静默丢弃，**不算错误**
- [ ] 异常帧：`01 83 02 xx xx` → 走异常路径，报"非法数据地址"
- [ ] 截断帧：少发最后一个字节 → 超时后报"帧不完整"
- [ ] 超长帧：长度字段写 0xFF → 直接丢弃，不进缓冲区越界

### 通过标准

六组全走对，且日志能打出「在第几个字节、因为什么原因失败」。

### 常见失败

| 现象 | 原因 |
|---|---|
| 偶发 CRC 错 | 把 CRC 两个字节也当数据算进了长度 |
| 03 应答解析错位 | 漏了"字节数"字段（03 应答的第 3 个字节是 N，不是数据） |
| 数组越界 | 长度字段没做上限检查（最大 253） |
| 异常帧当正常帧处理 | 没判功能码的 bit7 |

| 内容 | 有专门视频吗 | 怎么找 / 怎么用 |
