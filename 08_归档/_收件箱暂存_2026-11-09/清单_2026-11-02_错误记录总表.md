## 三、E01 详解：`sizeof` 与指针／数组

### 事实

```c
void mb_build_read(uint8_t *buf, uint16_t start, uint16_t cnt)
{
    uint8_t len = sizeof(buf);   /* 4 —— 不是缓冲区长度 */
}
```

形参 `uint8_t *buf` 是**指针**，数组传参时已退化为指针，`sizeof` 只回答"这个类型占几个字节"。指针宽 4（32 位 MCU），与缓冲区实际多大毫无关系。

### 我当时的错误链

1. 调用处手上是个数组 `uint8_t req[8]`，`sizeof(req) == 8` 成立
2. 把"在调用处成立"的性质带进了被调函数
3. 组包按 4 字节算长度 → 帧短了 / CRC 覆盖范围错
4. 从机不回或回异常，现象是"通信不通"，容易被误判成接线或波特率

### 正确写法（三种，按场景挑）

```c
/* ① 长度显式传（通用，最稳） */
void mb_build_read(uint8_t *buf, uint16_t buf_len,
                   uint8_t addr, uint16_t start, uint16_t cnt)
{
    const uint16_t need = 8;               /* RTU 03 请求固定 8 字节 */
    if (buf_len < need) return;            /* 出口保护，别信调用方 */
    ...
}

/* ② 定长帧：干脆不传长度，帧长编译期锁死 */
#define MB_REQ03_LEN  8u
uint8_t req[MB_REQ03_LEN];
_Static_assert(MB_REQ03_LEN == 8, "RTU 03 request must be 8 bytes");

/* ③ 只有"同一作用域内的数组名"才配用 sizeof */
#define ARRAY_SIZE(a)  (sizeof(a) / sizeof((a)[0]))   /* 绝不接收指针 */
```

### 记忆锚点

- `sizeof` 答的是**编译期类型大小**，答不了**运行期数据长度**。
- 看到 `sizeof` 出现在函数体里、操作数是形参 → 直接判错。
- 写组包/解析函数时，长度是**契约的一部分**，必须显式在参数表里或编译期常量里，不能"猜"。
